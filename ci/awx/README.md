# AWX on k3s

Two-step apply, on purpose. See `operator/kustomization.yaml` for why.

```sh
export KUBECONFIG=$HOME/.kube/config

# 1. operator + CRDs
kubectl apply -k ci/awx/operator

# 2. wait for the CRD to be established, then the instance
kubectl wait --for=condition=established --timeout=120s crd/awxs.awx.ansible.com
kubectl apply -f ci/awx/instance/awx.yml

# follow the reconcile
kubectl -n awx logs -f deploy/awx-operator-controller-manager -c awx-manager
```

The admin password is generated by the operator into a Secret. Nothing in this
repository carries it:

```sh
kubectl -n awx get secret awx-admin-password -o jsonpath='{.data.password}' | base64 -d
```

## Notes

- No sudo is needed anywhere. AWX runs entirely inside k3s, and `~/.kube/config`
  on the node is readable by the `neo` account.
- Ansible itself is installed per-user with `pipx install --include-deps ansible`.
  Without `--include-deps`, pipx exposes only `ansible-community` and there is
  no `ansible-playbook` on PATH.
- Single-node k3s: one replica, operator-managed PostgreSQL on the `local-path`
  StorageClass. This is a forge, not a production AWX - there is no HA, and a
  node loss means a restore from backup.
